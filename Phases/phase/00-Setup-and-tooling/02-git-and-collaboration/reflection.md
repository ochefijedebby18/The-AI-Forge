# Phase 00 — Lesson 02: Git & Collaboration

## 1. What I Learned

Before this lesson, I knew Git was used to manage code, but I did not fully understand how its workflow operated.

I now understand that Git helps developers track changes, maintain project history, create separate development branches, and collaborate without constantly interfering with the main project.

I learned the difference between the working directory, staging area, local repository, and remote repository.

I also learned that adding a file, committing changes, and pushing to GitHub are three different operations.

## 2. What I Practised

I completed several practical Git exercises:

- Created a `.gitignore` file to exclude large machine learning checkpoint files.
- Created the `feat/git-collaboration` branch.
- Created the `experiment/merge-practice` branch.
- Created a practice file and committed it.
- Switched back to my feature branch.
- Merged my experimental branch into my feature branch.
- Inspected my commit history using `git log`.
- Pushed my changes to GitHub.

I also updated my `LEARNING.md` file to record my lesson progress.

## 3. What I Understand Better Now

The most important thing I learned is that branches allow developers to experiment without immediately changing the main project.

I also understand that merging does not necessarily mean creating a new merge commit. In my exercise, Git performed a fast-forward merge because the destination branch had no diverging commits.

Another important lesson is that Git and GitHub are not the same thing. Git manages version control locally, while GitHub provides a remote platform where repositories can be hosted and shared.

## 4. Challenges I Encountered

One thing I initially needed to understand was why switching between branches matters.

I learned that creating a branch gives me a separate place to work. Switching branches changes which branch I am currently working on.

I also learned to inspect `git status` before committing or pushing changes. This helps me identify modified, staged, and untracked files.
